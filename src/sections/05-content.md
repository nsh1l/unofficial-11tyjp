# データとコンテンツ

記事を書く人に渡すのは、管理画面ではなくMarkdownの原稿です。見た目を直す仕事と本文を書く仕事を分ければ、サイトの構築をAIに手伝わせても、記事の内容は人の手元に残せます。

## 原稿の先頭に必要な情報を書く

フロントマターにタイトルや日付を置き、その下に本文を書きます。日付は公開日を意味するのか更新日を意味するのか、サイト内で決めて統一してください。原稿のファイル名やURLも、あとから変えると既存のリンクに影響します。

```md
---
title: はじめての記事
date: 2026-10-02
tags: [posts]
layout: base.njk
---
# はじめての記事

ここから本文です。
```

`tags: [posts]` は、記事一覧の材料にするための目印です。[フロントマター](https://www.11ty.dev/docs/data-frontmatter/)は本文とデータを分けて扱えます。原稿によって必要な項目を増やすときも、「何のために使うか」が説明できるものだけ追加します。

## 一覧は原稿から作る

同じタグのページは `collections.posts` で参照できます。たとえばNunjucksの一覧テンプレートでは、次のようにリンクを並べられます。

```njk
<ul>
{% for post in collections.posts %}
  <li><a href="{{ post.url }}">{{ post.data.title }}</a></li>
{% endfor %}
</ul>
```

記事を増やしたら一覧に自動で反映されます。ただし、**日付順や下書きの除外を勝手に期待しないこと**。並び順は[コレクションの仕様](https://www.11ty.dev/docs/collections/)を確認し、公開ルールに合わせて決めます。下書きは公開物に混ぜないよう、ビルド結果も確認してください。

## 共通情報は一か所へ

サイト名のように全ページで使う値は、[グローバルデータファイル](https://www.11ty.dev/docs/data-global/)に置けます。記事ごとのタイトルまで共通ファイルへ移す必要はありません。原稿を開いた人が、その記事の内容をその場で読める構成を優先します。

最後に記事のMarkdownを読み返し、ローカルプレビューで見出しやリンクを確認してから公開します。AIに校正を頼む場合も、固有名詞やリンク先の正しさは人が確かめます。
